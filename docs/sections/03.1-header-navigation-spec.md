# 03.1 Site header and navigation: section specification

**Status: SPECIFICATION. Awaiting approval of the direction. Not authorised for implementation.** 10/10/2026.

Composition preview (still frames, not the production header): `/dev/header`.

**Inputs not received.** The VNest logo and the website direction PDF named in the brief did not reach the working session. This specification follows the structure given in writing: logo left; Stay, Partner, Về VNest, Liên hệ in the centre; VI / EN right. In the preview the word "VNest" in plain text holds the logo's place. No mark has been drawn.

Statements about guests or conversion are hypotheses unless evidence is cited. None is validated.

## 1. Business objective

Let a guest know where they are and reach the four areas of the site, without competing with the hero or the booking bar for attention.

## 2. User intent and expected interactions

| Intent | Interaction |
|---|---|
| Recognise the brand, return home | Logo links to the homepage |
| Reach another area | Four text links on desktop; a menu button on phones and in the scrolled state |
| Change language | VI / EN selector. Only languages that exist are selectable |
| Keep searching while browsing | The compact booking bar stays in the header row after scrolling |

## 3. Contribution to direct booking

Hypothesis: a quiet header leaves the booking bar as the clearest action on the first screen. Hypothesis: keeping search in the header row after scrolling keeps booking one tap away. The header itself carries no booking call to action, so there is one, not two.

## 4. Proposed layout and visual direction

**At the top of the page (desktop, 1024px and up)**

- Transparent, 72px tall, over the hero. No background, no border.
- Three columns: logo left, navigation centred on the page (not on the leftover space), language right.
- Navigation: 15px, medium weight, 40px between items. Current page marked by a 1px underline set 8px below the text. Hover and focus use the same underline.
- Language: 13px, wider letter-spacing, "VI / EN".
- Legibility over imagery comes from a soft scrim at the top of the hero (about 130px, fading to nothing), not from a bar. Text is white over dark imagery and ink over light imagery.

**After scrolling past the hero**

- One solid row, 64px, warm surface with a single hairline beneath.
- The compact booking bar takes the centre. The four links move behind a two-line menu button on the right, beside the language selector.
- This is the answer to coexistence: **the header and the sticky booking bar are one row, never two.** 64px is about 7% of a 900px desktop screen.

**Motion.** The change between the two states is a short fade and slide using the existing duration tokens, which are zero under reduced motion. Nothing else animates.

## 5. SEO considerations

- A `<header>` with a `<nav aria-label>` containing real links, present in the server HTML.
- The menu's links are in the HTML on phones too, not injected on open.
- The current page is marked with `aria-current="page"`.
- Language links are plain links to the equivalent page, and exist only for languages that are enabled and approved, matching the `hreflang` rule already in the SEO layer.
- The logo is an image with alt text "VNest"; the page's `h1` belongs to the page, not the header.

## 6. Mobile behaviour

- Top of page: transparent row, 56px. Logo left, menu button right (44px target). The language selector lives in the menu, so the row holds two things.
- After scrolling: one 64px row with logo, compact search pill, menu button.
- Menu: a full-screen panel using the same native modal dialog pattern as the booking panel (focus trapped, page inert, Escape closes, focus returns). Large links (26px), language at the bottom.
- Under 1024px the header uses the menu button; the four inline links appear from 1024px, where they fit beside the logo and language without crowding.

## 7. Component structure (for implementation, once authorised)

```
src/config/navigation.ts        items: { id, label (localised), href }, in order
src/config/site.ts              logo: { src, width, height, alt }; enabledLocales (exists)
src/components/layout/
  SiteHeader.tsx                server component: logo, nav, language; reads config
  SiteLogo.tsx                  an image in a reserved box; swaps asset without layout change
  NavLinks.tsx                  the list, used inline and inside the menu
  LanguageSwitcher.tsx          renders only what is enabled
  MobileMenu.tsx                client: the one interactive part
```

- Navigation labels, routes, order and languages come from configuration. Nothing is hard-coded in components.
- **The logo is a slot.** `SiteLogo` takes a file path and its intrinsic size. The official SVG or horizontal wordmark replaces the temporary asset by changing one config entry. The box reserves height (28px desktop, 24px compact) so swapping never shifts the layout. The asset is shown as supplied: not redrawn, recoloured or cropped.
- Only `MobileMenu` and the scrolled-state switch need JavaScript. The header renders fully without it.

None. The header is static configuration. The language selector depends only on which locales are enabled and approved.

## 10. Alternatives and trade-offs

| Alternative | Trade-off | Position |
|---|---|---|
| Two rows after scrolling: header above the booking bar | All links stay visible | Rejected: about 120px of every screen, and twice that share on phones |
| Hide the header on scroll, show only the booking bar | Most space for content | Rejected: no logo or navigation while browsing |
| Keep the four links and shrink the booking bar beside them | Nothing moves behind a menu | Does not fit below about 1400px without crowding both |
| Solid header from the top of the page | Simplest, always legible | Cuts the hero and sits heavily above an immersive image |
| Menu button at all sizes, no inline links | Cleanest row | Hides four short labels on screens with room for them |
| **Proposed: inline links at the top, menu button after scrolling** | Links are one tap further away once scrolling | Booking stays in view, which is the product priority |

## 11. English, and what the selector may claim

English content does not exist and must not be implied. Two honest options:

| Option | Behaviour |
|---|---|
| A. Show "EN" as unavailable (as in the preview) | Visible but not a link, lower contrast, announced as unavailable. Keeps the agreed "VI / EN" composition; some guests will try it |
| B. Hide "EN" until English is approved | Nothing to misread. The right side of the header holds only "VI" or stays empty, which changes the balance |

Recommendation: **B at launch**, switching to the full selector when English is approved. An unavailable control in the header is a small dead end on every page. The preview shows A so the agreed three-part composition can be judged.

# 05.2 Bare Chic: property detail experience (reference implementation)

Date: 19/10/2026. Status: **plan APPROVED by the owner 19/10/2026 (D1–D5). Checkpoint 1 built, awaiting review** ([`../qa/05.2/cp1/RESULTS.md`](../qa/05.2/cp1/RESULTS.md)).

**20/10/2026:** VNest's workbook v2 was reconciled ([`../content/WORKBOOK-V2-SOURCE-DIFF-2026-10-20.md`](../content/WORKBOOK-V2-SOURCE-DIFF-2026-10-20.md)), and the owner's new brief was built on the same route ([`../qa/05.2/v2/RESULTS.md`](../qa/05.2/v2/RESULTS.md)). That brief supersedes parts of this plan: no former district, no nearby list, no policy line, no shared room facts, and per-room reference prices only. Its departures from checkpoint 1 are listed in that file and await review. The same day, it was refined at the owner's request: a room-grouped gallery and viewer, galleries per room, amenity highlights, comparable room cards, and "Khám phá các loại phòng" ([`../qa/05.2/v2-refine/RESULTS.md`](../qa/05.2/v2-refine/RESULTS.md)). The first build is kept at `/dev/stays/bare-chic-20-10`. Not approved.

One deviation from the plan, which the content model required: no amenity icons. An icon is VNest's choice, never guessed from a label.

Bare Chic is the first property built end-to-end on VNest's own content. It becomes the pattern the other five properties adapt from: shared parts, a page made distinctive by its own media, copy and composition. It must not be a template with the name swapped.

**SEO.**

- One H1 and a logical heading order.
- Metadata from `propertyPageSeo`.
- The record is a draft, so the page is `noindex` and has no structured data (`isPublishable` is false). Both switch on only when VNest approves the record. `lodgingJsonLd` already never states price, availability or rating.
- All content is in the first HTML response.


**Desktop (1440 px).** The Living Frames sheet:

- **Left:** the dominant frame, about 60% of the width.
- **Right:** a column with the two supporting frames and, below them, the identity block (eyebrow, H1, location, intro, price, CTA), kept apart from the pictures as chosen on 12/10.

Sections below alternate frame left and right (the prototype's chapter rhythm). Rooms appear as a two-column grid of compact blocks. Location and nearby share one row: the address card on the left, nearby in two columns on the right.

**Character.**

- **Palette:** the Brand Collection's VNest palette (olive, copper, beige, paper).
- **Type:** the Living Frames display face for H1 and section titles, if its file is approved (the prototype notes a lighter display font needs permission). Otherwise the site face.
- **Rules:** generous whitespace, copper hairlines.
- **Motion:** only a short fade-in on frames, off under reduced motion.
- **Excluded:** OTA badges, star ratings, review widgets, discount labels and tables.

**Performance.**

- Only the primary frame is high priority.
- Every other image is lazy, from the G2 derivatives (AVIF, WebP, JPEG).
- The viewer's script loads on first use.
- Budget: CLS below 0.05; LCP below 2.5 s on throttled 4G; added script within 20 KB gzip over the 05.1 shell, measured.

| Risk | Effect | Mitigation |
|---|---|---|
| Only one Bare Chic photo is authorised | The hero and three room blocks run on placeholders | G3 request above; placeholders designed as part of the page, not as gaps |
| Watermarks on Bare photos | Visible on full frames | Not edited. Ask VNest for unwatermarked originals (Q15) |
| Merged room facts | Risk of implying four rooms are identical | Shown once, marked as shared; no per-room claims until Q10 |
| Living Frames final visual not approved | Rework if the direction moves | Port only the accepted structure (one dominant, two supporting, identity apart, conventional CTA); keep the prototype as reference |
| 02.2 in review; compact blocks not built | Booking presentation may change | Build blocks inside 02.2 as its planned checkpoint; interim cards untouched |
| Script budget already 23 KB over in 05.1 | The page grows heavier | Measure per checkpoint; lazy-load the viewer; no new libraries |
| New content source in env/services | Composition-root change | Additive value used only by a local launch config; tests prove defaults unchanged |
| Moving the client adapter | Could break `b-client` | Pixel regression on `b-client` plus the prototypes before and after |
| Nearby list shared by four properties | Weak "relevance" | Present as "Quanh khu trung tâm"; per-property curation needs VNest input |
| Policies missing | A gap in the information section | Documented placeholder; booking unaffected |

## 7. Acceptance criteria

**Content and truth**

- [ ] Every visible fact traces to a workbook cell or a recorded source, with its status. Nothing invented: no amenities, distances, times, policies, prices or availability.
- [ ] Merged room facts are presented as shared; no per-room claim without a per-room source.
- [ ] Every frame names its room; no room photo stands for the property.
- [ ] Only authorised photos appear (G2 now, G3 if approved). Placeholders are clearly labelled.

**Booking**

- [ ] "Xem phòng trống" is in the first screen at 390 px, jumps to `#rooms` with the stay kept, and works without script.
- [ ] The rooms are 02.2's selection. With no PMS each shows the not-connected state; nothing simulates availability or price.
- [ ] Booking contracts and 02.1 are unchanged (diff is empty for `src/domain/booking*`, `ports.ts`, `src/features/booking-search/`).

**Design and quality**

- [ ] Living Frames structure preserved: one dominant frame, purposeful supporting frames, no carousel, no autoplay.
- [ ] 390, 768, 1440: no overflow; targets at least 44 px; keyboard path through the hero, viewer, rooms, map link and pill; reduced motion respected.
- [ ] SEO: one H1, logical headings, content in the first HTML response, `noindex` and no structured data while draft.
- [ ] Performance: CLS below 0.05; LCP within budget on throttled 4G; script measured against the 05.1 baseline.
- [ ] Brand Collection (`/a`, `/a-original`, `/b`, `/b-original`, `b-client`) pixel-identical; lint, typecheck, tests, build pass.
